## What changed

All four Gemini prompts implemented as pure async functions, plus a workflow orchestrator that chains them. Every prompt has a standalone `.test.ts` that hits Gemini for real and validates the output.

- **`lib/gemini/prompts/extractProfile.ts`** — Flash, temp 0.2. Maps raw Telegram onboarding answers → `Profile`. Parses company out of role, splits interests into tags, defaults availability to event-period slots.
- **`lib/gemini/prompts/rankMatches.ts`** — Flash, temp 0.3. Takes user profile + attendee list, returns top-N matches with specific, non-generic reasons. Strict instruction: copy attendee_id exactly, never invent UUIDs.
- **`lib/gemini/prompts/simulateConversation.ts`** — Pro, temp 0.7. Generates 4–8 turn alternating dialogue between user_agent and target_agent. Forces at least one realistic objection from the target. Outputs `target_interest` enum + `should_meet` boolean.
- **`lib/gemini/prompts/summarizeMatch.ts`** — Pro, temp 0.4. Produces final card copy: title (`<Name> · <angle>`), 2–3 sentence summary, one-sentence "why this matters", concrete opener line, 2–4 agenda bullets, confidence score.
- **`lib/orchestrator/workflow.ts`** — `runAgentWorkflow({ userProfile, userAvailability, attendees, topN, onEvent })`:
  - Emits `WorkflowEvent`s for `scanning`/`contacting`/`negotiating`/`scheduled`/`matched`/`rejected` — BE wires these to `graph_events` writes.
  - Processes candidates **in parallel** via `Promise.all`.
  - **Deterministic scheduling**: `findAvailabilityOverlap(userSlots, targetSlots, minMinutes)` returns the earliest ≥30-min overlap. No LLM call for this — saves latency and is reliable.
  - Skips `summarizeMatch` when `should_meet=false` — cheaper and emits `rejected` instead.
  - Returns sorted matches with full Conversation + MatchSummary attached.

## Why

Phase 4 of `TODO.md` is the AI track's main deliverable. With the orchestrator wired, BE can plug their DB writes into the `onEvent` callback and call `runAgentWorkflow` from `POST /api/agents/:id/start` — no further AI work required for the MVP.

Output quality is demo-grade: dialogue references actual availability slots, summaries name concrete next steps (e.g. "could become a design partner"), and weak fits are filtered out (rankMatches dropped a sales/crypto candidate; only 2/3 candidates passed).

## Performance notes

- E2E workflow ≈ 36 s for 3 candidates. Bottleneck is the two Pro calls per candidate. If demo latency matters, kick off `runAgentWorkflow` async and let the dashboard play seed-event animation while it runs.
- Parallelism is by `Promise.all` — fine up to ~5 candidates. Beyond that, add a concurrency cap.
- All prompts force JSON via `responseMimeType` + Zod validate. One auto-retry on bad output already burned in via `callGemini`.
